[OpenAI Codex](https://github.com/openai/codex) can use Mirage through an installable [TypeScript plugin](/typescript/agents/codex), a FUSE mount, or a [remote environment over SSH](#run-codexs-own-tools-over-ssh). The Python integration [FUSE-mounts](/python/setup/fuse) a workspace as a normal host directory, so Codex's built-in filesystem and shell tools operate on Mirage without a separate tool server.

## Install

```bash
uv add 'mirage-ai[fuse]'
```

Then install [OpenAI Codex](https://github.com/openai/codex) separately.

## Usage

```python
from mirage import Mount, MountBackend, MountMode, Workspace
from mirage.vfs.ram import RAMVFS

with Workspace(
    {"/": Mount(RAMVFS(), mode=MountMode.WRITE, backend=MountBackend.FUSE)}) as ws:
    print(f"cd {ws.fuse_mountpoint} && codex")
    input("Press Enter when done...")
```

The mountpoint behaves like a regular directory. Codex's built-in file and shell tools all dispatch through Mirage's ops layer. For the Codex app, open the mountpoint as the project folder instead of starting `codex` from it.

## Run Codex's own tools over SSH

Codex can keep its agent on your machine and run every tool call (shell
commands, file reads, `apply_patch`) in a remote environment. The Mirage
daemon serves that environment on its [SSH door](/home/ssh#run-codex-in-a-workspace)
as the `codex-exec` subsystem, so Codex's built-in tools work on the
workspace with no FUSE driver and no plugin.

1. Turn on the SSH door and create a workspace, as in [SSH Access](/home/ssh#turn-it-on).
2. Name the environment in `~/.codex/environments.toml`:

   ```toml
   default = "mirage"
   include_local = false

   [[environments]]
   id = "mirage"
   program = "ssh"
   args = ["-T", "-p", "2222", "demo@127.0.0.1", "-s", "codex-exec"]
   ```

3. Start Codex from a directory that exists on your machine, and use absolute workspace paths:

   ```bash
   codex -C /
   ```

Codex keeps its UI, sessions, model, approvals and login. Each command runs
in the login's Mirage session under its key's profile, and file calls follow
the mounts' modes. This route is for the Codex CLI; the Codex app's SSH
connections run the agent on the host, so they need Codex installed there.

## Which route?

Use Python FUSE when you want Codex's built-in filesystem tools to see Mirage as an ordinary directory. This works in the CLI and app, but requires an OS FUSE driver and does not add Mirage's agent-level stale-write check.

Use the SSH environment when Codex's built-in tools should run in a workspace the daemon serves, with no driver on your machine. It works in the CLI and runs under the SSH key's profile; like FUSE, it adds no stale-write check.

Use the [TypeScript plugin](/typescript/agents/codex) when you want named Mirage tools, Pi-style stale-write protection, and plugin installation through Codex. The plugin uses Mirage's standard MCP adapter internally.
