[Pyodide](https://pyodide.org) is full CPython compiled to WebAssembly, run
in a worker, with packages such as numpy loaded on import. The files it opens
are the workspace's, under the same mount modes and permissions as shell
commands. On supported Node versions, Mirage hardens the worker against
known host file, module, and network access paths after interpreter setup.
This is not a security boundary for hostile code; see
[containment](/typescript/runtime/python#containment) for limits and browser
behavior. Each command starts a fresh interpreter. TypeScript SDK
only, in Node and in browsers.

## Installation

```bash Node
pnpm add @struktoai/mirage-node pyodide
```

In a browser, install `@struktoai/mirage-browser` and `pyodide` instead. The page
must be cross-origin isolated for the worker; see
[worker and browser setup](/typescript/runtime/python#worker-and-browser-setup).

## Usage

<Tabs>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.EXEC, runtimes: ['pyodide'] })
    try {
      const inline = await ws.shell("python3 -c 'print(1 + 1)'")
      console.log(inline.stdoutText) // 2

      await ws.shell(`echo 'import sys; print(sys.argv[1:])' > /data/hello.py`)
      const script = await ws.shell('python3 /data/hello.py alice bob')
      console.log(script.stdoutText) // ['alice', 'bob']

      const piped = await ws.shell("echo 'print(1 + 1)' | python3")
      console.log(piped.stdoutText) // 2
    } finally {
      await ws.close()
    }
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    runtimes:
      - pyodide
    mounts:
      /data:
        vfs: ram
    ```
  </Tab>
</Tabs>

## Packages

[Pyodide's packages](https://pyodide.org/en/stable/usage/packages-in-pyodide.html),
such as numpy, load when a program imports them. The first import downloads
the package from the Pyodide CDN; Node keeps it beside the installed
`pyodide` package for later runs.

| Config key | What it does |
| --- | --- |
| `packages` | Load these when each interpreter starts, before the program runs. |
| `auto_load_from_imports` | Load what a program imports. Default `true`; `false` loads only `packages`. |
| `deny_packages` | Never download these for an import. An import still works when the package is reachable another way, such as through `sys_path`. |
| `sys_path` | Mount paths to put first on `sys.path`: directories, globs, or pure-Python `.whl` files. |
| `package_base_url` | Where packages download from; point it at your own copy to work offline. |

<Tabs>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'
    import { PyodideRuntime } from '@struktoai/mirage-core/runtime/python/pyodide'

    const runtime = new PyodideRuntime({
      config: {
        packages: ['numpy'],
        denyPackages: ['requests'],
        sysPath: ['/data/vendor', '/data/wheels/*.whl'],
      },
    })
    const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.EXEC, runtimes: [runtime] })
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    runtimes:
      - name: pyodide
        config:
          packages: [numpy]
          deny_packages: [requests]
          sys_path: [/data/vendor, /data/wheels/*.whl]
    mounts:
      /data:
        vfs: ram
    ```
  </Tab>
</Tabs>

A package from PyPI cannot be installed at run time: `micropip.install`
fails. Put its pure-Python wheel on a mount and list it in `sys_path`.

## Memory

`max_memory` caps the memory one run may grow to:

```yaml
runtimes:
  - name: pyodide
    config:
      max_memory: 256M
```

A run starts at about 50M. One that passes the cap fails with
`MemoryError`, and the next run starts fresh. On Node the run is stopped
as soon as it passes the cap; in a browser, which cannot read a worker's
memory, it fails when it ends. There is no cap by default.

## Python compatibility

The tables list supported APIs; expand **Limitations** for unsupported APIs
and runtime-specific restrictions. These sections describe how Python APIs
reach the workspace. Higher-level modules built on these calls, including
`os.path`, `pathlib`, `glob`, `shutil` and `json.load()`, work too.

Examples assume a writable `/data` mount. Mount modes and permissions still apply.

### `open()`

Modes and modifiers are listed separately; for example, `rb` combines `r`
and `b`. The file is read when it is opened.

| Mode or modifier | Support |
| --- | --- |
| `r` | ✓ |
| `w` | ✓ |
| `a` | ✓ |
| `x` | ✓ |
| `b` | ✓ |
| `t` | ✓ |
| `+` | ✓ |

<AccordionGroup>
  <Accordion title="Example: append to a workspace file" id="open-example">
    ```python
    with open("/data/log.txt", "a") as f:
        f.write("Job completed.\n")
    ```

  </Accordion>
  <Accordion title="Limitations" id="open-limitations">
    | API or behavior | Limitation |
    | --- | --- |
    | File access | Writes to workspace files follow mount permissions. Files created outside the mounts stay in memory and are lost when the run ends. |
