`E2BRuntime` connects to a live [E2B](https://e2b.dev) sandbox by id. Create
it with E2B's CLI or SDK, then expose any shared workspace files at matching
paths inside it. Using S3 through FUSE requires Mirage and `fuse3` in the
template; using the sandbox's native files through SSH/SFTP does not. Mirage
only connects and executes; it never
creates, starts, stops, or deletes the sandbox.

See the [Sandbox overview](/typescript/runtime/sandbox) for the shared image and
matching mount-prefix setup. The in-sandbox mount is served by the Python
Mirage build for both SDKs.

## Install

```bash
pnpm add e2b
```

## Configure

```yaml
runtimes:
  - name: e2b
    captures: ["python3", "pip"]
    config:
      sandboxId: ${E2B_SANDBOX_ID}
      apiKey: ${E2B_API_KEY}
  - vfs
```

`apiKey` is optional when `E2B_API_KEY` is set. The runtime connects on the
first captured line and reuses the sandbox client until the workspace closes.
Closing the workspace leaves the sandbox running.

The same configuration in application code is:

```ts
import { E2BRuntime } from '@struktoai/mirage-node'

const runtime = new E2BRuntime({
  captures: ['python3', 'pip'],
  config: { sandboxId: 'sandbox-id' },
})
```

Templates, CPU and memory sizing, networking, and lifecycle controls remain
E2B settings.

## Standard input

Piped input is sent as bytes to the command's native stdin, followed by an
explicit EOF. Empty input also sends EOF; a line without piped input starts
with stdin closed. This requires E2B SDK 2.45.0 or newer and a template
whose envd supports `CloseStdin`; rebuild an older template if the SDK reports
that closing stdin is unsupported. Input is buffered by the workspace before
execution, and stdout/stderr retain the SDK's text encoding.

This is the finite command interface. For an MCP server, keep a persistent
bidirectional stdio connection open through SSH instead. E2B documents an
[SSH over WebSocket setup](https://docs.e2b.dev/sandbox/ssh-access); a local
TCP bridge allows Mirage's existing SSH host/port configuration to use it.
Sandbox creation and bridge lifetime belong to the embedding application.

<Warning>
  Mirage timeouts stop waiting rather than terminating the remote process. E2B
  also applies its SDK command timeout, currently 60 seconds by default, to
  both runaway and legitimate long-running commands. See
  [Resource limits](/typescript/runtime/sandbox#resource-limits).
</Warning>
