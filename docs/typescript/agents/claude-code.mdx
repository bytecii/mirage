| Way | Claude Code gets | Needs |
| --- | --- | --- |
| [CLI](#cli) | Mirage's seven tools, beside its own | the `mirage` CLI |
| [FUSE](#fuse) | its own tools, on the workspace as a folder | a [FUSE driver](/home/setup/fuse) |

## Install

```bash
npm install -g @struktoai/mirage-cli
```

Install [Claude Code](https://docs.claude.com/en/docs/claude-code/setup) separately.

## Workspace

```yaml workspace.yaml
mode: write
mounts:
  /:
    vfs: ram
```

```bash
mirage workspace create workspace.yaml --id demo
```

## CLI

```bash
claude mcp add mirage -- mirage mcp -w demo
```

Claude Code gets `shell`, `read`, `write`, `edit`, `ls`, `grep` and `glob` from the workspace's [MCP server](/home/access/mcp).

## FUSE

Install your platform's [FUSE driver](/home/setup/fuse). On macOS, also follow the [macFUSE 4 workaround](/typescript/setup/fuse#macos-4-symlink-workaround). Then expose the RAM mount at a local folder:

```yaml workspace-fuse.yaml
mode: write
mounts:
  /:
    vfs: ram
    backend: fuse
    mountpoint: /tmp/mirage-demo
```

```bash
mirage workspace create workspace-fuse.yaml --id demo-fuse
cd /tmp/mirage-demo && claude
```

File operations under `/tmp/mirage-demo` go through Mirage. Claude Code still runs as a host process, so its shell and file tools can access paths outside that folder when host permissions allow. `mirage workspace delete demo-fuse` unmounts it. On macOS the daemon holds one FUSE mount at a time.
